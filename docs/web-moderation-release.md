# Web moderation release scope

From main `96f5910` only: normal-web safety controls on lobby/arena pages; existing web admin moderation queue; authenticated report/block APIs; basic name/chat filter; blocked-pair communication and new admission checks. Existing admin identity gate and wallet controls are unchanged. Reports do not automatically ban users or move gold. Active arena settlement remains unchanged.

The only additive database object is `hero_auction_moderation(id,state)` for the serialized single-process block/report store. Existing schema/data are not deleted or migrated. Successful restore logs `Moderation storage ready` without user data. Any persistence error also marks this store unavailable: a lost write acknowledgment may have committed, so in-memory rollback is not proof of database rollback. No later write or peer interaction is accepted until controlled restore/restart establishes the durable state. If this store is unavailable, new peer communications/admissions and friend/spectate disclosure fail closed; solo bot and existing match actions remain available. An operator must fix the store and restart/reload before peer interaction resumes.

Reports require a server-verified room seat or friend/request interaction. Responses expose only the caller's receipt; evidence and decision notes require the existing server-verified admin. Evidence includes a limited recent chat snapshot, not submitted client claims. Per-account rate limits, queue caps and 30-day report retention apply, with hourly persistent prune attempts. Outages/backups can delay physical deletion. This is a basic filter and review tool, not a claim of fully staffed abuse operations or legal compliance.

CrazyGames page transformation removes the new web safety scripts/styles; its separate SDK/English UI is not switched to the normal-web account controls. Shared server protections still enforce account interactions. No Capacitor/iOS files, native CORS, new auth provider, account deletion or new administrator grant is included.

Testing uses local ephemeral accounts and mocked storage; it does not mutate production accounts or verify actual PostgreSQL durability. Existing dependency manifests and aggregate test command remain unchanged. Browser/device visual QA was not run in this environment.

Release verification: 743 aggregate tests passed (including the original web regression suite, verified report intake/block protections, CG UI exclusion, persistence-failure gating, queued-admission checks and pending-unblock safety); strict 50-card audit and diff checks passed. Peer block decisions use only the last confirmed persisted/restored snapshot, so an unacknowledged unblock cannot temporarily enable communication. No live mutation or deployment was performed while preparing this branch.
